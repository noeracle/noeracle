How it works

You bring the price into your transaction.

Push oracles write state on a cadence; you read whatever the last write left behind. Noeracle inverts that — the consumer pulls a freshly signed price and verifies it on-chain, in the same transaction that uses it.

01 — FETCH

Pull a signed price

The SDK fetches a price attestation from the off-chain service, signed within the last ~500 ms.

02 — BUNDLE

Prepend the verify op

Add update_batch_ed25519_args to your own Stellar transaction, ahead of your logic.

03 — VERIFY

Checked on-chain

The Soroban contract verifies the signature, freshness and round — then your op runs against it.

WITH REFLECTOR

Built to complement Reflector, not replace it. Reflector pre-warms on-chain state for free, bounded-staleness reads — ideal for displays and anchor UIs. Noeracle hands you a freshly signed price to verify in your own transaction, for execution-time freshness.

Integration

Live in under ten lines.

The SDK is the product. If wiring up an oracle takes more than a few lines of TypeScript, the pull model has failed — so it doesn't.

consumer.ts 
import { Noeracle } from "@noeracle/sdk";

const oracle = new Noeracle({ network: "testnet" });

// a price signed within the last ~500 ms
const fresh = await oracle.fetchLatest(["BTC/USD"]);

// prepend the verification op to your transaction
tx.addOperation(fresh.toUpdateOp(ORACLE_CONTRACT_ID));

That is the whole consumer surface. Six lines — fetch, bundle, done.
